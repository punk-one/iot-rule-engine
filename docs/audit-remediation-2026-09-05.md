## 结论

本轮已消除会直接导致引擎进程崩溃、静默降级、共享事件竞态、遗留消费者抢占消息和未受信插件直接执行的主要代码级风险。引擎目前具备发布候选基线，但原 NATS 凭证轮换与 Git 历史清理、插件沙箱、登录限流、共享会话、UI 仓库归属和长稳压测仍是发布前或后续版本工作，不能由代码修改替代。

| 维度 | 当前判断 | 依据 |
| --- | --- | --- |
| 可靠性 | B+ | 关键服务受统一监督；失败会退出；关闭等待运行面；扇出返回部分失败 |
| 稳定性 | B+ | Event 分支独占；订阅可关闭/恢复；关键路径与全量 race 门禁纳入 CI |
| 可扩展性 | B | SDK v1 边界明确、插件依赖移出引擎、单 artifact 进程复用；全局 bus 仍限制多实例测试 |

## 关键架构约束

1. 插件传给引擎的 Event 在 Publish 边界立即克隆，插件不得依赖 Publish 后的共享修改。
2. 每个调度任务及每个下游分支拥有独立 Event；不得把可变 Metadata/Payload 当作跨任务通信区。
3. `RuleID`、`FromNode`、`ToNode`、开始/结束时间属于调度上下文，不写入业务 Metadata。
4. 一个 canonical plugin artifact 只启动一个 OS 进程；每个规则节点创建独立的进程内插件对象和反向 RPC 通道。
5. 运行面只使用受 Engine 生命周期管理的订阅句柄；退出前必须 Close。
6. 引擎仓不得直接依赖 MQTT、数据库等正式插件驱动，插件之间只共享 SDK v1 API。
7. Connector 插件进程与外部连接分离：一个 artifact 一个进程；S7 按近期采集需求
   复用、FANUC 每操作短连接、MQTT 长连接，数据库和 Redis 使用连接池。

## 发布前必须人工完成

1. 吊销已泄露的 NATS 用户，轮换所有相关凭证并清理 Git 历史。
2. 发布并固定 `iot-rule-plugin-sdk` 的 `v1.0.0` tag，CI 和构建不得依赖本地 replace。
3. 若开启在线插件安装，先在发布流水线验证签名，再把对应 release manifest 只读挂载给引擎；不允许客户端同时上传 manifest。
4. 在目标 Linux、数据库和外部 NATS 环境完成故障注入、升级回滚与至少 24 小时长稳压测。
