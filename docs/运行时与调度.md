# Ingress 架构文档（v1.3.1）

## 📋 概述

Ingress 是规则引擎的**唯一协议接入边界**，负责将外部协议数据（HTTP、MQTT、SparkplugB）转换为统一的 Event 格式，并发布到 NATS 供 Source Plugin 处理。

**核心原则**：
- Ingress 是唯一的协议接入边界，所有外部数据必须通过 Ingress 接入
- Ingress 只做协议转换，不处理业务逻辑
- Ingress 发布 **Raw Event** 到 `ingress.{protocol}.raw`，由 Source Plugin 负责过滤和处理
- Source Plugin 不直接监听端口或连接 Broker，只订阅 NATS Event

## 📦 主要组件

### 1. Ingress 主入口 (`internal/server/ingress/ingress.go`)

**职责**：
- 启动和管理所有协议适配器（HTTP、MQTT）
- 创建 Event Bridge
- 处理下行命令事件

**关键方法**：
- `Run(ctx, cfg)`: 启动 Ingress，初始化所有协议适配器
- `handleCommandEvent(event)`: 处理下行命令事件（待实现）

### 2. Event Bridge (`internal/server/ingress/eventbridge/bridge.go`)

**职责**：
- 将协议数据转换为统一的 Event 格式
- 发布 Raw Event 到 NATS Topic: `ingress.{protocol}.raw`
- 订阅和处理下行命令事件

**关键方法**：
- `PublishRaw(protocol, event)`: 发布 Raw Event 到 `ingress.{protocol}.raw`
- `SubscribeCommandEvents(handler)`: 订阅命令事件（`ingress.command.>`）

**Raw Event 结构**：
```go
type Event struct {
    ID        string                 // 事件ID（UUID）
    Timestamp time.Time              // 时间戳
    Payload   map[string]interface{} // 业务数据（包含协议原始数据）
    Metadata  map[string]string      // 元数据（protocol, hint.* 等）
}
```

### 3. HTTP Ingress (`internal/server/ingress/http/http_ingress.go`)

**职责**：
- 接收 HTTP POST 请求
- 构建 Raw Event 并发布到 `ingress.http.raw`

**接入端点**：
- `POST /ingress/http` 或 `POST /ingress/http/*`
- 健康检查：`GET /health`

**Raw Event 结构**：
```json
{
  "id": "uuid",
  "timestamp": "2024-01-01T00:00:00Z",
  "payload": {
    "path": "/ingress/http",
    "raw": "base64_encoded_body"
  },
  "metadata": {
    "protocol": "http",
    "method": "POST",
    "client": "127.0.0.1:12345",
    "content_type": "application/json"
  }
}
```

### 4. MQTT Ingress (`internal/server/ingress/mqtt/mqtt_ingress.go`)

**职责**：
- 作为 MQTT Broker（基于 mochi-mqtt）
- 通过 Hook 机制捕获所有 MQTT 消息
- 识别 SparkplugB Topic（`spBv1.0/` 前缀）
- 构建 Raw Event 并发布到 `ingress.mqtt.raw` 或 `ingress.sparkplugb.raw`

**MQTT Hook**：
- 实现 `mqtt.Hook` 接口
- `OnPublish`: 核心逻辑，处理所有 MQTT 消息发布

**SparkplugB Topic 识别**：
- Topic 格式：`spBv1.0/{group}/{MSG}/{node}/{device?}`
- MSG 类型：`NBIRTH`, `DBIRTH`, `NDATA`, `DDATA`, `DCMD`, `NCMD`, `NDEATH`, `DDEATH`
- 自动提取 `hint.*` 元数据：
  - `hint.group`: Group ID
  - `hint.msg`: 消息类型
  - `hint.node`: Node ID
  - `hint.device`: Device ID（如果有）

**Raw Event 结构（MQTT）**：
```json
{
  "id": "uuid",
  "timestamp": "2024-01-01T00:00:00Z",
  "payload": {
    "topic": "sensor/data",
    "raw": "base64_encoded_payload"
  },
  "metadata": {
    "protocol": "mqtt",
    "client_id": "client-123",
    "qos": "0",
    "retain": "false",
    "username": "user1"
  }
}
```

**Raw Event 结构（SparkplugB）**：
```json
{
  "id": "uuid",
  "timestamp": "2024-01-01T00:00:00Z",
  "payload": {
    "topic": "spBv1.0/Factory/DDATA/Line1/Motor1",
    "raw": "base64_encoded_protobuf"
  },
  "metadata": {
    "protocol": "sparkplugb",
    "client_id": "client-123",
    "qos": "0",
    "retain": "false",
    "hint.group": "Factory",
    "hint.msg": "DDATA",
    "hint.node": "Line1",
    "hint.device": "Motor1"
  }
}
```

### 5. Dispatcher (`internal/core/dispatcher/dispatcher.go`)

**职责**：
- 订阅所有 `ingress.*.raw` Topic
- 将 Raw Event 分发给所有注册的 Source Plugin
- 通过 `PluginClient.SendEvent()` 统一分发

**关键方法**：
- `onIngressRaw(data)`: 处理 Ingress Raw Event，分发给所有 Source Plugin

**分发逻辑**：
```go
// Dispatcher 订阅 ingress.*.raw
ingressSubject := "ingress.*.raw"

// 收到 Raw Event 后，分发给所有规则的 Source Plugin
for _, rule := range d.rules {
    for nodeID, pClient := range rule.Plugins {
        if pClient.Info().Type == sdk.PluginTypeSource {
            // 非阻塞分发（Source Plugin 自己决定是否处理）
            go func(nid string, cl client.PluginClient, evt sdk.Event) {
                if err := cl.SendEvent(evt); err != nil {
                    utils.Debug("Source plugin %s rejected raw event: %v", nid, err)
                }
            }(nodeID, pClient, event)
        }
    }
}
```

## 🔄 数据流转流程

### 1. HTTP 数据流

```
外部系统/设备
    ↓ HTTP POST /ingress/http
HTTP Ingress (internal/server/ingress/http/)
    ├── 读取请求体
    ├── 构建 Raw Event（包含 base64 编码的 body）
    └── Event Bridge.PublishRaw("http", event)
    ↓
NATS Topic: ingress.http.raw
    ↓
Dispatcher (internal/core/dispatcher/)
    ├── 订阅 ingress.*.raw
    ├── 收到 Raw Event
    └── 分发给所有 Source Plugin（通过 PluginClient.SendEvent）
    ↓
HTTP Source Plugin (pkg/plugins/sources/http_source/)
    ├── OnEvent() 接收 Raw Event
    ├── 解析 payload.raw（base64 解码）
    ├── 设置 source_id = ctx.NodeID()
    └── EngineRPC.Emit() → Dispatcher.OnPluginEmit()
    ↓
NATS Edge Topic: rule.edge.{ruleID}.{fromNodeID}.{toNodeID}
    ↓
Dispatcher → Processor/Sink Plugin
```

### 2. MQTT 数据流

```
MQTT Client
    ↓ MQTT Publish (topic: sensor/data)
MQTT Broker (mochi-mqtt)
    ├── Hook.OnPublish() 捕获消息
    └── Event Bridge.PublishRaw("mqtt", event)
    ↓
NATS Topic: ingress.mqtt.raw
    ↓
Dispatcher
    ├── 订阅 ingress.*.raw
    └── 分发给所有 Source Plugin
    ↓
MQTT Source Plugin (pkg/plugins/sources/mqtt_source/)
    ├── OnEvent() 接收 Raw Event
    ├── 提取 payload.topic 和 payload.raw
    ├── 设置 source_id = ctx.NodeID()
    └── EngineRPC.Emit() → Dispatcher.OnPluginEmit()
    ↓
NATS Edge Topic → Processor/Sink Plugin
```

### 3. SparkplugB 数据流

```
SparkplugB Client
    ↓ MQTT Publish (topic: spBv1.0/Factory/DDATA/Line1/Motor1)
MQTT Broker (mochi-mqtt)
    ├── Hook.OnPublish() 捕获消息
    ├── 识别 Sparkplug Topic（spBv1.0/ 前缀）
    ├── 解析 Topic 提取 hint.* 元数据
    └── Event Bridge.PublishRaw("sparkplugb", event)
    ↓
NATS Topic: ingress.sparkplugb.raw
    ↓
Dispatcher
    ├── 订阅 ingress.*.raw
    └── 分发给所有 Source Plugin
    ↓
Sparkplug Source Plugin (pkg/plugins/sources/sparkplug_source/)
    ├── OnEvent() 接收 Raw Event
    ├── 检查 protocol == "sparkplugb"
    ├── 根据 hint.group 过滤（必须匹配配置的 group_id）
    ├── 根据 hint.msg 过滤（如果配置了 msg_types）
    ├── 解析 Sparkplug Protobuf payload
    ├── 为每个 metric 创建独立事件
    ├── 设置 source_id = ctx.NodeID()
    └── EngineRPC.Emit() → Dispatcher.OnPluginEmit()
    ↓
NATS Edge Topic → Processor/Sink Plugin
```

## 🔧 Source Plugin 配置

### 1. HTTP Source (`pkg/plugins/sources/http_source/`)

**配置结构**：
```json
{
  "source_id": "http-source-1"
}
```

**配置字段**：
- `source_id` (string, 必需): Source 标识符，用于标识该 Source Plugin

**功能**：
- 通过 `OnEvent()` 接收 Raw Event（由 Dispatcher 分发）
- 解析 `payload.raw`（base64 解码）
- 设置 `source_id = ctx.NodeID()`
- 发布事件到 DAG

**注意**：
- HTTP Source 在 v1.3.1 中仍然使用旧的订阅机制（`ingress.http.{source_id}`），但应该迁移到 Raw Event 模式
- 未来版本将完全使用 `OnEvent()` 接收 Raw Event

### 2. MQTT Source (`pkg/plugins/sources/mqtt_source/`)

**配置结构**：
```json
{
  "source_id": "mqtt-source-1"
}
```

**配置字段**：
- `source_id` (string, 必需): Source 标识符，用于标识该 Source Plugin

**功能**：
- 通过 `OnEvent()` 接收 Raw Event（由 Dispatcher 分发）
- 提取 `payload.topic` 和 `payload.raw`
- 设置 `source_id = ctx.NodeID()`
- 发布事件到 DAG

**注意**：
- MQTT Source 在 v1.3.1 中仍然使用旧的订阅机制（`ingress.mqtt.{source_id}`），但应该迁移到 Raw Event 模式
- 未来版本将完全使用 `OnEvent()` 接收 Raw Event

### 3. Sparkplug Source (`pkg/plugins/sources/sparkplug_source/`)

**配置结构**：
```json
{
  "group_id": "Factory",
  "msg_types": ["NDATA", "DDATA"]
}
```

**配置字段**：
- `group_id` (string, 必需): Sparkplug Group ID，用于过滤 `hint.group`
- `msg_types` (array[string], 可选): 消息类型过滤，如 `["NDATA", "DDATA"]`。如果为空或未配置，接受所有类型

**功能**：
- 通过 `OnEvent()` 接收 Raw Event（由 Dispatcher 分发）
- 检查 `protocol == "sparkplugb"`
- 根据 `hint.group` 过滤（必须匹配配置的 `group_id`）
- 根据 `hint.msg` 过滤（如果配置了 `msg_types`）
- 解析 Sparkplug Protobuf payload（从 `payload.raw` base64 解码）
- 为每个 metric 创建独立事件
- 设置 `source_id = ctx.NodeID()`
- 发布事件到 DAG

**过滤逻辑**：
```go
// 1. 检查协议类型
if e.Metadata["protocol"] != "sparkplugb" {
    return nil // 忽略非 SparkplugB 事件
}

// 2. 根据 hint.group 过滤
if hintGroup != s.groupID {
    return nil // group 不匹配，忽略
}

// 3. 根据 hint.msg 过滤（如果配置了）
if len(s.cfg.MsgTypes) > 0 {
    if hintMsg not in s.cfg.MsgTypes {
        return nil // msg 类型不匹配，忽略
    }
}
```

## 🔑 关键设计原则

### 1. Ingress 是唯一协议接入边界

- ✅ 所有外部数据必须通过 Ingress 接入
- ❌ Source Plugin 不直接监听端口、不连接 Broker
- ✅ Source Plugin 只订阅 NATS Event

### 2. Raw Event 模式（v1.2+）

- Ingress 只做协议转换，不处理业务逻辑
- Ingress 发布 Raw Event 到 `ingress.{protocol}.raw`
- Source Plugin 负责过滤和处理 Raw Event
- Source Plugin 根据 `hint.*` 元数据过滤事件

### 3. 协议无关性

- Ingress 层处理协议细节（HTTP、MQTT、SparkplugB）
- Source Plugin 只处理 Event，不关心协议
- 通过 `metadata.protocol` 标识协议类型
- 通过 `hint.*` 元数据提供协议特定信息

### 4. 可扩展性

- 新增协议只需实现新的 Ingress 适配器
- Source Plugin 无需修改即可支持新协议
- 通过 `hint.*` 元数据支持协议特定功能

## 📝 注意事项

### 1. Source Plugin 迁移

- HTTP Source 和 MQTT Source 当前仍使用旧的订阅机制（`ingress.{protocol}.{source_id}`）
- 应该迁移到 Raw Event 模式（通过 `OnEvent()` 接收 Raw Event）
- Sparkplug Source 已完全使用 Raw Event 模式

### 2. Command 事件处理

- Command 事件通过 `ingress.command.{protocol}` Topic 发布
- Ingress 订阅 Command 事件并分发到对应的协议适配器
- Command 处理逻辑待实现（当前为 TODO）

### 3. 性能考虑

- Raw Event 发布是异步的（非阻塞）
- Dispatcher 分发 Raw Event 也是异步的（goroutine）
- Source Plugin 应该快速处理 Raw Event，避免阻塞

## 🔮 未来改进

1. **统一 Raw Event 模式**：所有 Source Plugin 都使用 `OnEvent()` 接收 Raw Event
2. **Command 处理实现**：完成下行命令事件的处理逻辑
3. **协议扩展**：支持更多协议（gRPC、WebSocket 等）
4. **性能优化**：批量处理、连接池等优化

# Command Event 标准规范 v1

> **定位一句话**
> Command Event 标准规范是**规则引擎 / Plugin SDK / Ingress 三方之间的"契约级文档"**。
> 它的目标不是描述实现细节，而是**冻结语义边界**，保证后续 3～5 年的可演进性。

> **状态**：Draft → Stable
> **适用范围**：Rule Engine Core / Plugin SDK v1.1 / Ingress Runtime
> **关键词**：Command、DAG、Ingress、Protocol Adapter

---

## 1. 设计目标（一句话）

> **Command Event 是规则引擎对外部系统发起“控制行为”的唯一标准载体。**

它必须满足：

* Source / Processor / Sink **统一模型**
* 与 Telemetry Event **完全对称**
* Ingress **零规则感知**
* 可 Trace / 可审计 / 可回放

## 3. Command Event 定义（统一结构）

### 3.1 Event 顶层结构（不区分 Telemetry / Command）

```json
{
  "id": "uuid",
  "ts": "2025-01-01T12:00:00Z",
  "payload": {},
  "meta": {}

```

> ⚠️ **Command Event ≠ 新 Event 类型**
> 它是 **通过 `meta.intent = command` 进行语义标识**

## 4. Command Event Meta 规范（核心）

### 4.1 Meta 字段定义（v1 强制）

| -------------- | ------- | -- | -------------------------------- |

| protocol       | string  | 🔶 | 目标协议（sparkplugb / modbus / http） |

| command_type   | string  | 🔶 | device / service / config        |
| reply_expected | boolean | 🔶 | 是否期望设备 ACK                       |
| timeout_ms     | number  | 🔶 | 命令超时时间                           |
| trace_id       | string  | ✅  | 全链路 Trace                        |
| rule_id        | string  | ✅  | 规则实例 ID                          |
| node_id        | string  | ✅  | 当前节点 ID                          |

## 5. Command Source Plugin 规范

### 5.1 职责边界（必须遵守）

Command Source Plugin **只负责语义产生**：

* 谁（device / service）
* 做什么（command）
* 用什么参数

❌ **禁止**：

* 协议拼装
* MQTT Topic 计算
* Sparkplug / Modbus SDK 调用

---

### 5.2 Command Source 输出约束

| 项目       | 约束            |
| -------- | ------------- |
| intent   | 必须为 `command` |
| protocol | 可为空           |
| payload  | 协议无关          |
| 出口       | 只能是 NATS      |

---

## 6. Command Sink Plugin 规范（协议感知层）

### 6.1 Command Sink 的定位

> **Command Sink = Command Event → Protocol Command Event 的翻译器**

它做三件事：

1. 校验 Command Event 是否适用于该协议
2. 将 payload 转换为协议模型
3. 生成 **Ingress 可识别的 Command Event**

#### 输入 Event（来自 DAG）

```json
    "device_id": "plc-01",

    "value": 1200
  },
  "meta": {
    "intent": "command",
    "protocol": "sparkplugb"
  }
}
```

```json
{
  "payload": {
    "group": "factory-1",
    "node": "line-01",
    "device": "plc-01",
    "metrics": [
      {
        "name": "set_speed",

      }
    ]
```

| --------- | ---------------------------- |

| 是否访问 MQTT | ❌ 禁止                         |

## 7. Ingress 对 Command Event 的处理规范

### 7.1 Ingress 订阅模型

Ingress 必须订阅：

```
ingress.command.>
```

并按 `meta.protocol` 分发到对应 Adapter。

---

### 7.2 Ingress 的职责（冻结）

Ingress **只做**：

1. 权限校验（ACL）
2. 协议编码（Sparkplug / Modbus / HTTP）
3. 下发到设备

Ingress **绝不做**：

* 规则判断
* 条件逻辑
* 命令生成

### 12.1 数据流向对比

| 方向   | Telemetry Event                    | Command Event                      |
| ---- | ---------------------------------- | --------------------------------- |
| 起点   | Ingress（协议接入）                      | Command Source Plugin（规则起点）        |
| 终点   | Sink Plugin（数据输出）                   | Ingress（协议下发）                      |

| ------ | ---------------------- | ---------------------- |

| 插件类型        | Telemetry 场景              | Command 场景              |
| ----------- | ------------------------- | ----------------------- |

| Processor   | 处理 Telemetry Event          | 处理 Command Event（校验/转换）  |
| Sink        | 输出到外部系统（数据库/API）          | 转换为协议 Command Event        |

# 规则运行态模型文档 v1.1

## 1️⃣ 设计目标

### 1.1 为什么需要运行态模型？

配置态（Canvas / Rule Definition）只回答：

> **规则“长什么样”**

运行态模型回答的是：

> **规则现在“跑成什么样”**

---

### 1.2 运行态模型必须解决的问题

| 问题         | 说明              |
| ---------- | --------------- |
| 规则是否在运行    | 状态机             |
| 哪个节点卡住     | NodeInstance    |
| 数据是否丢失     | EdgeInstance 统计 |

| Trace 如何定位 | runtime_id 贯穿   |

# 规则部署与运行态关系说明

## 概述

本文档说明规则引擎中规则部署、取消部署与运行态（Runtime）之间的关系和处理逻辑。

## 核心概念

### 1. 规则部署（Deploy）

**触发方式**：
- 通过 Manager API `POST /api/v1/rules/:id/deploy` 触发
- 前端 UI "部署" 按钮调用此接口

**处理流程**：
1. Manager 获取规则配置
2. 校验规则（`validateRule`）
3. 设置 `rule.Enabled = true`
4. **版本号自增**：`rule.Version++`
5. 保存到数据库（`db.SaveRule(rule)`）
6. Executor 通过 DB Watch 机制自动检测到规则变化
7. Executor 调用 `UpdateDAGFromJSON` 更新 DAG
8. 如果版本号变化或启用状态变化，调用 `UnregisterDAG` 停止旧实例
9. 重新构建 DAG 并调用 `RegisterDAG`
10. 如果规则启用，调用 `startRuleInstance` 启动新实例

**关键逻辑**：
- **版本号管理**：每次部署都会自增版本号，用于区分不同的部署版本
- **实例替换**：如果存在旧版本的运行实例，会先停止旧实例，再创建新实例
- **版本检查**：`startRuleInstance` 会检查是否已存在相同版本的运行实例，如果存在且版本相同，则跳过创建

### 2. 规则取消部署（Undeploy/Disable）

**触发方式**：
- 通过 Manager API `POST /api/v1/rules/:id/disable` 触发
- 前端 UI "取消部署" 按钮调用此接口

**处理流程**：
1. Manager 获取规则配置
2. 设置 `rule.Enabled = false`
3. **版本号不变**：取消部署不会改变版本号
4. 保存到数据库（`db.SaveRule(rule)`）
5. Executor 通过 DB Watch 机制自动检测到规则变化
6. Executor 调用 `UpdateDAGFromJSON` 更新 DAG
7. 由于 `Enabled = false`，会调用 `UnregisterDAG` 停止所有相关实例
8. `UnregisterDAG` 执行以下操作：
   - 停止 DAGNATSExecutor
   - 停止并移除所有 Plugin Instances
   - **停止该规则的所有 RuleInstance**（不管当前状态如何）
   - 删除 DAG 映射
9. 不会调用 `startRuleInstance`（因为规则已禁用）

**关键逻辑**：
- **实例清理**：`UnregisterDAG` 会停止该规则的所有实例（包括 `running`、`created`、`paused` 等状态）
- **状态转换**：实例状态会从当前状态转换为 `stopped`，并设置 `StoppedAt` 时间戳
- **资源释放**：清理 DAG 映射、插件实例等资源

### 3. 运行态（Runtime）

**数据来源**：
- Runtime API 通过 Manager 代理到 Executor
- Executor 的 `runtimeMgr.ListRuleInstances()` 返回所有 RuleInstance

**显示规则**：
- **只显示 `running` 状态的实例**：运行态页面只显示状态为 `running` 的实例
- **实例去重**：对于同一规则 ID 的多个实例，使用以下优先级选择：
  1. 优先选择 `running` 状态的实例
  2. 如果状态相同，选择版本号更高的实例
  3. 如果版本号相同，选择创建时间更晚的实例

**关键逻辑**：
- **状态过滤**：`ListRuleInstancesHandler` 会过滤掉所有非 `running` 状态的实例
- **版本显示**：运行态显示的版本号是当前运行实例的版本号，对应规则配置中的版本号

## 状态转换

### RuleInstance 状态转换

```
created → running → stopped
   ↓         ↓         ↑
   └─────────┴─────────┘
   (UnregisterDAG 或 startRuleInstance 替换)
```

### 规则部署流程状态转换

**部署新版本**：
1. 旧实例：`running` → `stopped` (通过 `UnregisterDAG` 或 `startRuleInstance` 中版本检查)
2. 新实例：`created` → `running` (通过 `startRuleInstance`)

**取消部署**：
1. 所有实例：当前状态 → `stopped` (通过 `UnregisterDAG`)

## 版本管理

### 版本号规则

- **部署时**：版本号自增 (`rule.Version++`)
- **取消部署时**：版本号不变
- **编辑规则时**：版本号不变（除非部署）

### 实例与版本的关系

- 每个 RuleInstance 都有 `Version` 字段，对应创建时的规则版本号
- 运行态显示的是当前运行实例的版本号
- 如果规则被取消部署后重新部署，版本号会自增，运行态会显示新版本号

### 版本冲突处理

当部署新版本时：
1. `UpdateDAGFromJSON` 检测到版本号变化，调用 `UnregisterDAG` 停止旧版本的所有实例
2. `startRuleInstance` 再次检查是否存在运行中的实例
3. 如果存在运行中的实例但版本不同，会先停止旧实例
4. 然后创建新版本的实例

## 常见场景

### 场景 1：部署规则

1. 用户点击 "部署" 按钮
2. Manager 设置 `Enabled = true`，版本号自增（例如：1 → 2）
3. Executor 检测到变化，停止旧实例（版本 1），启动新实例（版本 2）
4. 运行态显示版本 2 的实例

### 场景 2：取消部署

1. 用户点击 "取消部署" 按钮
2. Manager 设置 `Enabled = false`，版本号不变（例如：仍为 2）
3. Executor 检测到变化，停止所有实例（状态变为 `stopped`）
4. 运行态不再显示该规则（因为只显示 `running` 状态的实例）

### 场景 3：编辑后重新部署

1. 用户编辑规则（版本号不变，例如：仍为 2）
2. 用户点击 "部署" 按钮
3. Manager 设置 `Enabled = true`，版本号自增（2 → 3）
4. Executor 检测到版本变化，停止旧实例（版本 2），启动新实例（版本 3）
5. 运行态显示版本 3 的实例

### 场景 4：部署后取消部署再部署

1. 规则版本 1，已部署（运行态显示版本 1）
2. 取消部署（版本仍为 1，运行态不再显示）
3. 部署（版本自增为 2，运行态显示版本 2）

1. **版本号一致性**：运行态显示的版本号应该与规则配置的版本号一致（对于已部署的规则）
2. **实例清理**：取消部署后，所有相关实例都应该被停止，运行态不应再显示
3. **状态过滤**：运行态页面只显示 `running` 状态的实例，已停止的实例不应显示
4. **版本冲突**：部署新版本时，应确保旧版本的实例被正确停止，避免同时运行多个版本
5. **DB Watch 延迟**：由于 DB Watch 是轮询机制（1秒间隔），从部署到运行态更新可能有最多1秒的延迟

```go
func InitJetStream(opts NATSOptions) error {
    var natsOpts []nats.Option

    // 支持多种认证方式：user, token, tls
    switch opts.AuthMode {
    case "user":
        natsOpts = append(natsOpts, nats.UserInfo(opts.Username, opts.Password))
    case "token":
        natsOpts = append(natsOpts, nats.Token(opts.Token))
    case "tls":
        if opts.CertFile != "" && opts.KeyFile != "" {
            natsOpts = append(natsOpts, nats.ClientCert(opts.CertFile, opts.KeyFile))
        }
        if opts.CAFile != "" {
            natsOpts = append(natsOpts, nats.RootCAs(opts.CAFile))
        }
    }

    nc, err := nats.Connect(opts.URL, natsOpts...)
    if err != nil {
        return fmt.Errorf("failed to connect to NATS: %w", err)
    }

    js, err := nc.JetStream()
    if err != nil {
        nc.Close()
        return fmt.Errorf("failed to get JetStream context: %w", err)
    }

    globalJS = &JetStreamClient{
        nc: nc,
        js: js,
    }

    // 初始化必需的 Streams
    if err := initStreams(js); err != nil {
        return fmt.Errorf("failed to initialize streams: %w", err)
```

```go
// WatchConfig 监听单个 key 的变更
func (c *KVClient) WatchConfig(key string, onUpdate func([]byte) error, onDelete func() error) error {
    watcher, err := c.kv.Watch(key)
    if err != nil {
        return fmt.Errorf("failed to watch key %s: %w", key, err)
    }

    go func() {
        for {
            select {
            case entry := <-watcher.Updates():
                if entry == nil {
                    return  // 通道关闭
                }

                if entry.Operation() == nats.KeyValuePut {
                    if err := onUpdate(entry.Value()); err != nil {
                        utils.Error("Error handling update for key %s: %v", key, err)
                    }
                } else if entry.Operation() == nats.KeyValueDelete {
                    if err := onDelete(); err != nil {
                        utils.Error("Error handling delete for key %s: %v", key, err)
                    }
                }
            }
        }
    }()

    return nil
}

// WatchAll 监听整个 bucket 的变更
func (c *KVClient) WatchAll(onUpdate func(string, []byte) error, onDelete func(string) error) error {
    go func() {
        retryDelay := 1 * time.Second
        maxRetryDelay := 30 * time.Second

        for {
            watcher, err := c.kv.WatchAll()
            if err != nil {
                utils.Error("Failed to watch all keys, retrying in %v: %v", retryDelay, err)
                time.Sleep(retryDelay)
                retryDelay *= 2  // 指数退避
                if retryDelay > maxRetryDelay {
                    retryDelay = maxRetryDelay
                }
                continue
            }

            retryDelay = 1 * time.Second  // 重置重试延迟

            // 持续监听，直到 watcher 真正停止
            for entry := range watcher.Updates() {
                if entry == nil {
                    // 通道关闭（nil）表示所有现有数据已发送完毕
                    // 这是正常行为，继续监听
                    continue
                }

                key := entry.Key()
                if entry.Operation() == nats.KeyValuePut {
                    if err := onUpdate(key, entry.Value()); err != nil {
                        utils.Error("Error handling update for key %s: %v", key, err)
                    }
                } else if entry.Operation() == nats.KeyValueDelete {
                    if err := onDelete(key); err != nil {
                        utils.Error("Error handling delete for key %s: %v", key, err)
                    }
                }
            }

            // watcher 停止，重启
            watcher.Stop()
            utils.Warn("KV watcher stopped unexpectedly, restarting in %v...", retryDelay)
            time.Sleep(retryDelay)
        }
    }()

    return nil
}
```

**功能说明**：
- `WatchConfig`: 监听单个 key 的变更，支持更新和删除回调
- `WatchAll`: 监听整个 bucket 的变更，支持自动重连和指数退避
- 处理 `nil` entry：NATS KV 的 `WatchAll()` 在发送完所有现有键值对后会发送 `nil`，这是正常行为，表示初始数据已发送完毕

##### 3.4 获取所有配置

```go
// GetAll 获取所有配置（用于 Pull on Start）
func (c *KVClient) GetAll(onEntry func(key string, value []byte) error) error {
    watcher, err := c.kv.WatchAll()
    if err != nil {
        return fmt.Errorf("failed to watch all keys: %w", err)
    }
    defer watcher.Stop()

    processed := make(map[string]bool)
    timeout := time.NewTimer(5 * time.Second)
    defer timeout.Stop()

    for {
        select {
        case entry := <-watcher.Updates():
            if entry == nil {
                // 通道关闭，所有现有键已读取完毕
                return nil
            }

            key := entry.Key()
            // 只处理每个键一次（避免重复）
            if !processed[key] && entry.Operation() == nats.KeyValuePut {
                processed[key] = true
                if err := onEntry(key, entry.Value()); err != nil {
                    return err
                }
            }
        case <-timeout.C:
            // 超时后停止读取
            return nil
        }
    }
}
```

**功能说明**：
- 用于启动时拉取所有现有配置
- 使用 `WatchAll()` 获取初始数据，5 秒超时
- 去重处理，避免重复读取

```go
type FifoScheduler struct {
	queue chan *DispatchTask
	wg    sync.WaitGroup
	stop  chan struct{}
}

func NewFifoScheduler(buffer int) *FifoScheduler {
	return &FifoScheduler{
		queue: make(chan *DispatchTask, buffer),
		stop:  make(chan struct{}),
	}
}

func (s *FifoScheduler) Start() error {
	s.wg.Add(1)
	go s.loop()
	return nil
}

func (s *FifoScheduler) Stop() error {
	close(s.stop)
	s.wg.Wait()
	return nil
}

func (s *FifoScheduler) Submit(task *DispatchTask) error {
	select {
	case s.queue <- task:
		return nil
	default:
		return errors.New("scheduler queue full")
	}
}

func (s *FifoScheduler) loop() {
	defer s.wg.Done()
	for {
		select {
		case task := <-s.queue:
			execute(task) // 👉 唯一执行入口
		case <-s.stop:
			return
		}
	}
}
```

```go
package plugin

import (
	"errors"
	"sync"
	"time"
)

type MemoryRegistry struct {
	mu        sync.RWMutex
	instances map[string]*PluginInstance
	runner    InstanceRunner
}

func NewMemoryRegistry(runner InstanceRunner) *MemoryRegistry {
	return &MemoryRegistry{
		instances: make(map[string]*PluginInstance),
		runner:    runner,
	}
}

func (r *MemoryRegistry) Register(inst *PluginInstance) error {
	r.mu.Lock()
	defer r.mu.Unlock()

	if _, ok := r.instances[inst.ID]; ok {
		return errors.New("instance already exists")
	}

	inst.Status = InstanceCreated
	inst.CreatedAt = time.Now()
	inst.UpdatedAt = inst.CreatedAt

	r.instances[inst.ID] = inst
	return nil
}

func (r *MemoryRegistry) Start(id string) error {
	r.mu.Lock()
	inst, ok := r.instances[id]
	r.mu.Unlock()

	if !ok {
		return errors.New("instance not found")
	}

	if err := r.runner.Start(inst); err != nil {
		inst.Status = InstanceFailed
		return err
	}

	inst.Status = InstanceRunning
	inst.UpdatedAt = time.Now()
	return nil
}

func (r *MemoryRegistry) Stop(id string) error {
	r.mu.Lock()
	inst, ok := r.instances[id]
	r.mu.Unlock()

	if !ok {
		return errors.New("instance not found")
	}

	if err := r.runner.Stop(inst); err != nil {
		return err
	}

	inst.Status = InstanceStopped
	inst.UpdatedAt = time.Now()
	return nil
}

func (r *MemoryRegistry) Remove(id string) error {
	r.mu.Lock()
	defer r.mu.Unlock()

	delete(r.instances, id)
	return nil
}
```

```go
// pkg/router/validate.go
package router

import (
	"errors"
	"fmt"

	"yourproject/pkg/rule"
)

func ValidateGraph(g *rule.RuleGraph) error {
	nodes := map[string]rule.Node{}
	for _, n := range g.Nodes {
		nodes[n.ID] = n
	}

	for _, e := range g.Edges {
		from, ok := nodes[e.From]
		if !ok {
			return fmt.Errorf("edge from node not found: %s", e.From)
		}
		to, ok := nodes[e.To]
		if !ok {
			return fmt.Errorf("edge to node not found: %s", e.To)
		}

		if e.Emit == "" {
			return fmt.Errorf("edge emit must be explicit: %s -> %s", e.From, e.To)
		}

		if from.Type == rule.NodeSink {
			return errors.New("sink node cannot emit events")
		}
		if from.Type == rule.NodeSource && to.Type == rule.NodeSource {
			return errors.New("source to source is forbidden")
		}
	}

	return validateDAG(g)
}
```

## 3️⃣ DAG 校验（防隐式执行）

```go
func validateDAG(g *rule.RuleGraph) error {
	graph := map[string][]string{}
	for _, e := range g.Edges {
		graph[e.From] = append(graph[e.From], e.To)
	}

	visited := map[string]bool{}
	stack := map[string]bool{}

	var dfs func(string) error
	dfs = func(n string) error {
		if stack[n] {
			return fmt.Errorf("cycle detected at %s", n)
		}
		if visited[n] {
			return nil
		}
		visited[n] = true
		stack[n] = true
		for _, next := range graph[n] {
			if err := dfs(next); err != nil {
				return err
			}
		}
		stack[n] = false
		return nil
	}

	for _, n := range g.Nodes {
		if err := dfs(n.ID); err != nil {
			return err
		}
	}
	return nil
}
```

### 实现骨架

```go
// pkg/scheduler/rule_scheduler.go
package scheduler

import (
	"context"
	"sync"
)

type RuleScheduler struct {
	queues map[string]chan Task
	mu     sync.Mutex
}

func NewRuleScheduler() *RuleScheduler {
	return &RuleScheduler{
		queues: make(map[string]chan Task),
	}
}

func (s *RuleScheduler) Schedule(ctx context.Context, task Task) error {
	s.mu.Lock()
	q, ok := s.queues[task.RuleID]
	if !ok {
		q = make(chan Task, 1024)
		s.queues[task.RuleID] = q
		go s.runQueue(ctx, q)
	}
	s.mu.Unlock()

	q <- task
	return nil
}

func (s *RuleScheduler) runQueue(ctx context.Context, q chan Task) {
	for {
		select {
		case <-ctx.Done():
			return
		case task := <-q:
			_ = task.Exec(ctx)
		}
	}
}

func (s *RuleScheduler) Stop() error {
	return nil
}
```

```go
func (d *DefaultDispatcher) Submit(ctx context.Context, evt runtime.Event) error {
	ruleNodes := d.nodes[evt.RuleID]
	if ruleNodes == nil {
		return nil
	}

	node := ruleNodes[evt.NodeID]
	if node == nil {
		return nil
	}

	task := scheduler.Task{
		RuleID: evt.RuleID,
		NodeID: evt.NodeID,
		Event:  evt,
		Exec: func(ctx context.Context) error {
			return d.executeNode(ctx, node, evt)
		},
	}

	return d.scheduler.Schedule(ctx, task)
}
```

```go
	ctx context.Context,
	node *runtime.RuntimeNode,
	evt runtime.Event,

	results, err := node.Plugin.Execute(ctx, evt.Data)
	if err != nil {
		return err

			Data:   r.Data,
		}

	}

	return nil
}
```

```go
// pkg/runtime/db_loader.go
package runtime

import (
	"errors"

	"yourproject/pkg/plugin"
	"yourproject/pkg/router"
)

type DBLoader struct {
	db          RuleDB
	pluginMgr   plugin.Manager
}

func (l *DBLoader) Load() (*Snapshot, error) {
	rules, err := l.db.ListEnabledRules()
	if err != nil {
		return nil, err
	}

	snap := &Snapshot{
		Rules: map[string]*RuleRuntime{},
	}

	for _, r := range rules {
		graph := r.Graph

		rtRouter, err := router.NewRouter(&graph)
		if err != nil {
			return nil, err
		}

		nodes := map[string]*RuntimeNode{}
		for _, n := range graph.Nodes {
			exec, err := l.pluginMgr.Create(n.Plugin, n.Config)
			if err != nil {
				return nil, err
			}
			nodes[n.ID] = &RuntimeNode{
				RuleID: r.ID,
				NodeID: n.ID,
				Type:   string(n.Type),
				Plugin: exec,
			}
		}

		snap.Rules[r.ID] = &RuleRuntime{
			RuleID: r.ID,
			Router: rtRouter,
			Nodes:  nodes,
		}
	}

	if len(snap.Rules) == 0 {
		return nil, errors.New("no enabled rules loaded")
	}
	return snap, nil
}
```

# 五、Dispatcher 执行 Trace（关键）

## 1️⃣ 执行包装器（唯一位置）

```go
func (d *DefaultDispatcher) executeNode(
	ctx context.Context,
	node *runtime.RuntimeNode,
	evt runtime.Event,
) error {

	span := trace.NewSpan(evt, node)
	start := time.Now()

	results, err := node.Plugin.Execute(ctx, evt.Data)

	span.End = time.Now()
	span.Cost = span.End.Sub(start)

	if err != nil {
		span.Status = trace.SpanError
		span.Error = err.Error()
		trace.Collect(span)
		return err
	}

	if len(results) == 0 {
		span.Status = trace.SpanDrop
		span.Meta["reason"] = "no_emit"
		trace.Collect(span)
		return nil
	}

	span.Status = trace.SpanOK
	trace.Collect(span)

	for _, r := range results {
		out := runtime.Event{
			RuleID: evt.RuleID,
			NodeID: node.NodeID,
			Emit:   r.Emit,
			Data:   r.Data,
		}
		PublishToRouter(ctx, out)
	}

	return nil
}
```
