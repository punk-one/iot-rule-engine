# iot-rule-engine 复审整改与验证记录（2026-09-18）

本记录对应 `reaudit-2026-09-18.md`。整改遵循“不启动真实 PLC、MQTT 或生产插件”的验证边界。

## 已完成

- REA-01：移除当前部署脚本和部署说明中的固定远程密码，改为运行环境注入。历史 Git 对象仍需在发布前使用专用工具清理，并轮换曾出现过的凭据。
- REA-02：Connector API 返回的 `connection` 递归脱敏；更新接口接受秘密占位符并保留已存秘密；同步失败响应不再回显原始资源。
- REA-03：`Executor.Execute` 现在把输入消息注入正在运行的 Dispatcher，不再“只校验后返回成功”；规则实例启动失败会清理 DAG 并返回错误。DryRun 在没有插件级副作用隔离契约前明确返回 501，不再报告虚假成功。
- REA-04：在线配置接口拒绝修改 Manager 端口、数据库路径、存储类型和初始化模式；UI 同步锁定启动级字段。
- REA-05：SQLite 保存改为事务内乐观并发控制，旧版本保存返回冲突，规则和快照原子提交；增加回归测试。
- REA-06：新建/普通编辑不能直接写入启用状态；部署或启用后的 Executor 同步、运行态确认失败会自动回滚为禁用；列表状态来自实际运行实例与版本。
- REA-07：规则编辑加载采用请求序列保护；切换规则时先清空旧实体，失败后禁止保存旧规则。
- REA-08：SQLite 规则及 Connector watcher 仅在所有订阅者成功后推进游标；失败会在下一轮重试；增加失败后重试测试。
- REA-09：规则列表的部署、取消部署、启用、禁用和删除统一按规则互斥；编辑页部署按钮也在请求期间禁用。
- REA-10：前端 API 增加 15 秒超时，避免请求无限挂起。
- REA-11：bcrypt 并发槽改为过载快速拒绝，返回 429 和 `Retry-After`，不再形成无界等待队列。
- REA-13：NATS `.creds` 改为主机文件路径输入，不再误用 PEM 证书上传接口。

## 发布前仍需处理

- PostgreSQL 后端仍需补齐与 SQLite 等价的事务 CAS 和 watcher 失败重试；当前默认开发配置使用 SQLite。
- 登录接口仍建议增加按来源 IP/用户名的速率限制；本轮已先限制高成本 bcrypt 的全局并发。
- Axios 已有超时，但页面级请求取消仅对规则编辑加载使用请求序列隔离，其他长列表仍可逐步接入 AbortSignal。
- REA-12 的单文件运行、入口服务说明和 systemd 首次管理员 secret 注入需要单独作为部署工程完成。
- 发布到 GitHub 前必须清理历史对象中的旧凭据并轮换外部凭据；仅修改当前工作树不足以清除历史。

## 兼容性说明

- Connector API 的 `connection` 中秘密字段现在返回 `__IOT_RULE_SECRET_SET__`，前端回传该值表示保留原值。
- 旧版本规则更新现在返回 HTTP 409，客户端应重新加载后再编辑。
- DryRun 暂时返回 HTTP 501；在 SDK 定义并由所有 Sink 强制执行副作用隔离前，不提供伪隔离执行。
