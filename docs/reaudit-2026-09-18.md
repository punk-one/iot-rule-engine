## 后端、安全与数据一致性

### REA-01 · P1 · 发布资料仍有明文密码

**位置：** `deploy/README.md:110` 的 `REMOTE_PASSWORD` 示例包含具体密码值，并与真实部署主机上下文放在一起。该文件是 Git 跟踪文件。本报告不重复密码、不测试其有效性。

此外，`git log --all -- configs/nats-sun-back.creds configs/nats-sun2.creds` 仍能定位到历史提交 `6bc4bc5`。仅确认路径进入过历史，不推断当前凭证仍可用。删除工作树文件不等于处理完公开历史。

**影响：** 直接公开仓库可能公开部署凭证和实际环境信息；与 AGENTS 中“不在示例放真实端点/凭证”的要求冲突。

**建议与验收：** 将部署示例改为保留域名/地址和明确占位符；审查部署脚本的秘密默认值及传递方式；对可能有效的密码/凭证完成轮换；授权后处理公开历史并做全历史扫描。验收应有脱敏检查及轮换记录，不能只删除一行说明。

### REA-02 · P1 · Connector 原始连接配置未脱敏

**位置：** `internal/server/manager/handlers/connector_contracts.go:43,466–477`；`connector_handlers.go:17–46,49–62`；`internal/server/manager/router.go:230–238`。

`ConnectorResourceView` 嵌入完整 `sdk.ConnectorResource`，构建视图时直接复制资源，包含 `Connection`。即使 connection_preview/summary 选择安全字段，原始 connection 仍在 JSON 中。读取资源路由有通用鉴权，但没有 requireAdmin 或独立秘密读取权限。

**复现：** 临时 SQLite 保存合成 password 标记，GET 列表返回 200，响应包含标记。复现直接调用 handler；普通已登录用户可到达该 handler 是独立路由静态证据，不声称匿名可读取。

**影响：** 可读取 Connector 的用户可获得业务 broker/数据库连接秘密；列表批量扩大暴露范围。

**建议与验收：** 引入明确的公开 DTO，敏感字段只返回“已设置”；保存时保留未修改秘密；独立设计秘密更新和删除语义，优先使用 secret reference。覆盖列表、详情、兼容资源列表、错误响应和导出，确保合成秘密在非秘密操作响应中均不存在。

### REA-03 · P1 · 普通规则输入和 DryRun 执行空转

**位置：** `internal/core/engine/executor.go:448–491`；`internal/server/executor/executor.go:320–341`；`internal/server/manager/handlers/deploy_handlers.go:163–222`；`ui/src/components/DryRunConsole.tsx:28–33,114–116`。

`Execute` 仅检查 DAG 和 enabled，然后返回 nil；没有调用节点或交给 Dispatcher。服务端 rule.input 消费者在 nil 后 ACK。DryRun 同样调用这个方法，随后返回 success 和原输入消息。

**复现：** 向注册了计数探针节点的 DAG 执行普通消息和 dry-run 消息，两次均返回 nil，节点调用次数均为 0。

**影响：** 到达旧 rule.input 执行入口的有效消息可能被确认却不产生节点处理；调试控制台的成功不能证明 JS/转换/路由逻辑正确。**这不等于 S7/MQTT Source 插件当前直连 Dispatcher 的路径全部失效**，两条入口要区别看待。

**建议与验收：** 明确保留还是退役旧输入链路。保留时转交实际入口 Dispatcher，按既定投递语义决定 ACK；退役时禁止假接受。DryRun 应使用独立测试实例和替代外部副作用的 connector/emitter，返回真实逐节点结果；未实现前明确返回不支持。增加合成 source→transform→sink 的输出断言，不能只断言 HTTP 200。

### REA-04 · P1 · 启动字段可在线改写，可能切换至空数据库

**位置：** `internal/server/manager/handlers/config_handlers.go:75–118`；`internal/infra/config/validation.go:22–46`；`loader.go:119–139,171`；`internal/server/engine.go:39–53`；`ui/src/components/ConfigForm.tsx:199–213`。

API 的语义校验检查端口合法范围，没有拒绝 manager.port、db_path、storage_type 等启动定位字段变化。UI 只禁用了端口，数据库路径仍可编辑。

**复现：** 原配置端口 11011；PUT 修改为测试端口并改变临时 db_path，返回 200，两者均进入持久化配置。

**影响：** 重启时先通过 YAML 找到旧库，读取旧库中的新路径，再由 Engine 打开新路径；可能创建空库、规则/用户“消失”，或者因缺少初始化管理员密码而启动失败。改端口也不会自动修改开发 UI 地址或部署反向代理。

**建议与验收：** 普通配置 API 对启动字段使用不可变白名单约束；存储迁移和监听地址调整走专用流程。旧库到新库要有备份、迁移校验和回滚。API 非法变更应明确失败且原配置不变；需要迁移时单独验证用户、规则及连接资源完整性。

### REA-05 · P1 · SQLite 旧版本保存可回退版本并覆盖新内容

**位置：** `internal/infra/storage/rulesdb/sqlite_db.go:173–237`；`internal/server/manager/handlers/rule_handlers.go:94–125`。

SaveRule 仅在传入版本“等于当前版本”时递增。旧客户端传入较小版本会原样写入；读取旧版本、更新规则及生成快照之间也没有事务/CAS 保证。

**复现：** A/B 同时读取版本 3；A 先保存成为 4；B 再保存仍带版本 3，保存成功，最终版本从 4 回到 3，内容变为 B 的陈旧内容。该复现不依赖 goroutine 调度。

**影响：** 多标签页、多人编辑、部署与保存竞争时可能丢失新配置，运行态版本对照及快照记录失真。

**建议与验收：** 版本由服务端单调递增；客户端传 expectedVersion/If-Match；事务中 CAS 更新，冲突返回 409，规则与快照原子提交。覆盖旧版本、并发部署/取消部署和客户端任意填大版本，不能只测试顺序保存。

### REA-06 · P1 · 部署、保存与运行态状态不一致

**位置：** `rule_handlers.go:55–91,94–125,168–177`；`deploy_handlers.go:48–73,438–452`；`internal/core/engine/executor.go:590–604`。

三个相关缺口：

1. CRUD 保存允许客户端直接写 enabled/version，没有统一执行部署校验；后台监听会尝试应用。
2. 列表状态只按 enabled 和 version > 1 判断 deployed，没有核对 runtime。
3. 实例启动失败只记日志，UpdateDAGFromJSON 仍返回 nil；等待函数只检查实例存在，不检查 running 和期望版本。部署 handler 先保存 enabled 再同步，失败后数据库仍保留该状态。

**复现：** 创建 enabled=true、version=3、nodes=[] 的规则返回 201；无运行实例时列表仍报告 deployed。实例启动失败的完整流程本轮为代码审查证据，没有注入真实插件故障。

**影响：** 操作者可能把“已保存/已启用”当作“已运行”，部署失败后刷新仍显示成功；通过普通保存可能绕过部署入口要求。

**建议与验收：** 区分草稿、期望部署版本、实际运行版本、失败状态；普通保存不能隐式部署；实例启动错误向上传递；等待同时核对 running 与版本。建立单规则事务/操作互斥和幂等语义。验证冷启动缺插件、初始化失败、并发操作和超时重试，UI 应显示一致的真实状态。

### REA-08 · P2 · 数据库监听提前推进游标，失败不重试

**位置：** `internal/infra/storage/rulesdb/sqlite_db.go:525–560,604–638`；`internal/server/executor/executor.go:278–291`。

监听在通知订阅者前更新 lastData；回调失败只记录日志。后续同一配置不再被认为有变化。Executor 规则回调还把处理失败转换为 nil。Connector 也存在相同的提前记录逻辑。

**复现：** 回调固定返回一次合成错误；等待首次通知后再跨过 3 个以上轮询周期，总回调次数仍为 1。

**影响：** 瞬时插件/资源错误可能使数据库已保存但运行面长期未应用，直到再次编辑或重启。

**建议与验收：** 每个订阅者维护独立 desired/applied version，失败采用有界退避重试，持续暴露同步失败状态；成功订阅者不重复应用。验证一次失败后自动恢复、多个订阅者局部失败，以及删除失败。

### REA-11 · P2 · 登录限流没有覆盖排队数量

**位置：** `internal/server/manager/router.go:164–170`；`internal/server/manager/userauth/service.go:172–188`。

上轮增加的 bcrypt 并发上限 4 和会话容量治理仍存在，但获取 authSlots 是无 context 的阻塞发送。路由没有账号/来源限速；大量请求仍可排队，客户端断开也不能取消该等待。

**影响：** 可访问登录接口的客户端能占用等待请求和 goroutine；限制“正在算 bcrypt”的数量不等于限制总登录负载。本轮未对服务发起攻击压测。

**建议与验收：** 引入请求 context、有界等待/快速 429、账号+来源限速和可信代理策略；统一认证失败信息。隔离压测确认请求取消释放资源、队列有上界，正常登录不被长期饿死。

## 前端与前后端契约

### REA-07 · P1 · 编辑器跨规则保留旧内容，存在误改风险

**位置：** `ui/src/store/ruleStore.ts:43–53`；`ui/src/pages/RuleEditorPage.tsx:22–32,58–79,141–155`。

请求 B 时不清空 A，也没有请求代际防止迟到响应；请求失败只保存 error。编辑器不读取 loading/error，也不以 currentRule.id === 路由 id 作为渲染/保存前提；保存使用当前 store 中的规则 ID。

**复现：** 运行真实 store 代码，先放入 A，再模拟获取 B 返回 404：requested=B、retainedRule=A、loading=false。页面继续呈现和保存 A 的结论来自对应 UI 代码，未进行真实浏览器点击复现。

**影响：** 地址栏显示 B，但用户看到并可能修改 A；初次加载失败且没有旧数据时则持续显示“加载中”。较慢的历史请求还可能覆盖较新的路由内容。

**建议与验收：** 以请求 ID 或 AbortController 拒绝过期结果，切换时进入明确加载状态，加载错误清理旧编辑上下文；渲染/保存核对路由 ID，撤销历史随规则隔离。测试 A→B失败、A/B响应乱序、退出登录后切换用户、404 不自动误建规则。

### REA-09 · P2 · 启停操作绕过规则按钮锁

**位置：** `ui/src/pages/RuleListPage.tsx:70–91,162–190,193–197,521–533`；`RuleEditorPage.tsx:93–138`。

部署/取消部署已有同步 ref 锁，但列表“已启用/已停用”按钮直接调用 enable/disable，不进入这把锁，也未绑定 pending 禁用。编辑器部署/取消部署同样没有统一 pending 互斥。后端 disable 就是取消部署路径。

**影响：** 部署进行中仍可点状态按钮发起相反请求，或者重复启停；前端主按钮修复没有覆盖全部入口。结合 REA-05/06 可能出现状态竞争。

**建议与验收：** 为同一 ruleID 统一保存/启停/部署/删除的操作状态；所有入口共享同步防重，并让后端保证幂等及冲突拒绝。测试连点状态按钮、部署时点停用、多个标签页反向操作。

### REA-10 · P2 · UI 请求无统一超时和取消

**位置：** `ui/src/services/api.ts:29–35`；`ui/src/auth/AuthContext.tsx:56–77`；`RuleListPage.tsx:193–233`。

axios 实例未配置 timeout；页面请求也普遍未传取消 signal。请求迟迟不结束时，登录恢复 loading、规则 pending、资源刷新可能持续等待。后端 HTTP 超时不能覆盖浏览器与代理之间所有连接故障。

**建议与验收：** 设置分场景超时、路由卸载取消和过期响应保护；超时后查询操作状态，避免盲目重试部署等写请求。用不会响应的模拟请求验证状态能退出，并显示可理解的恢复操作。

### REA-13 · P2 · NATS creds 上传控件与 API 不兼容

**位置：** `ui/src/components/ConfigForm.tsx:189–190`；`internal/server/manager/handlers/config_handlers.go:156,216–258`。

前端为 creds 模式提供“上传 NATS creds 文件”，复用证书上传接口；后端只接受指定类型的 X.509/PKCS PEM，NATS JWT/seed creds 不在允许集合。

**影响：** 正常 NATS creds 文件经该 UI 上传会被拒绝，配置外部 NATS 时形成无法完成的操作路径。不能通过放宽为任意文件上传来消除验证。

**建议与验收：** 优先把 creds 改为受限挂载路径/secret 引用，并在 UI 明示；确需上传时设计独立、受大小限制、可校验且不回显 seed 的处理。使用合成 creds 测试，不使用真实凭证。
