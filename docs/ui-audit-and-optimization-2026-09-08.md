# iot-rule-engine Web UI 审计与优化方案

审计日期：2026-09-08
审计范围：`ui/src` 中的登录、工作台、规则、运行态、插件、Connector、系统配置与用户管理页面。
审计方式：页面代码与路由审查、样式与可访问性静态统计、现有测试审查、生产构建与本地服务可达性验证。

## 1. 结论

当前 Web 已经能够覆盖规则引擎的主要管理和运维流程，登录页、工作台、Connector 页面和运行态页面也已形成初步的产品化表达；但登录后的各页面仍处于“多次迭代叠加”的状态，最突出的问题不是缺少视觉效果，而是缺少统一的交互与样式约束。

建议不要立即进行大范围换肤，而是按以下顺序优化：

1. 先建立统一页面骨架、设计令牌、按钮和异步状态规范。
2. 优先重构高频使用的规则列表、Connector 和配置页面。
3. 再优化规则编辑器与运行态监控的空间利用、信息层级和可访问性。
4. 最后完成性能、响应式、端到端测试和视觉回归基线。

目标是让系统达到以下状态：操作状态明确、同类控件表现一致、窄屏可用、键盘可操作、异常可恢复，并使后续新增插件或页面不再复制页面内样式。

## 2. 当前基础

### 2.1 已有优点

- 主路由已按页面懒加载，能够避免所有业务页面一次性进入首屏。
- 已使用 Ant Design `ConfigProvider` 设置主色和基础圆角，并有 `FeedbackProvider` 统一消息、确认和输入弹窗。
- 登录页使用 CSS Module，具备 960px 和 640px 两档响应式布局，是当前完成度最高的页面之一。
- `ConsolePage`、`ConsoleHeader`、`StatCard` 已提供页面容器的早期抽象。
- 规则列表已增加单条规则操作锁，部署或取消部署期间能阻止重复请求。
- 现有 19 个测试套件、53 个测试全部通过，覆盖了主要页面和部分复杂组件。
- 本地 UI 与健康检查接口均返回 HTTP 200，生产构建成功。

## 3. 主要问题与优先级

### P0：需要优先处理

#### 3.1 页面操作体系不统一

规则列表使用大量彩色原生按钮和 Emoji，Connector、插件页主要使用 Ant Design，配置页又使用另一套原生按钮。相同含义的“刷新、保存、删除、启用”在尺寸、颜色、禁用、加载和反馈方式上不同。

影响：

- 用户需要重复学习操作含义。
- 新页面容易继续复制现有样式。
- 重复提交、等待状态和错误恢复容易遗漏。

建议：

- 统一使用 `Button` 或封装后的 `ActionButton`。
- 每个页面只保留一个主操作，次要操作使用默认按钮，低频操作放入“更多”菜单。
- 所有异步操作必须有 `loading`、`disabled`、成功反馈、错误反馈和结束后的数据刷新。
- 删除、停用、取消部署等破坏性操作统一二次确认。

#### 3.2 响应式布局仅覆盖登录页

应用头部包含 Logo、6 个一级导航和用户入口，同时导航容器设置了最小宽度。规则列表固定最小宽度 1280px；多数页面只有自动换行，没有针对 1024px、768px 和手机宽度的布局策略。

影响：

- 1024px 工控屏或分屏窗口容易出现导航折行和内容挤压。
- 规则表格依赖横向滚动，关键操作列可能离开视区。
- 模态框和复杂表单在窄屏上难以完成操作。

建议：

- 大于等于 1200px 保留横向一级导航；小于 1200px 切换为菜单按钮和抽屉导航。
- 统一页面内容断点：1200、992、768、480。
- 规则列表在 992px 以下切换为摘要卡片或固定首列、操作列，并明确横向滚动提示。
- 所有筛选栏采用可折叠 FilterBar；手机宽度下表单控件占满一行。

#### 3.3 异步状态和错误恢复不完整

工作台已经区分加载、空数据和错误，但规则列表、配置页、运行态页面仍使用各自的文本块。配置首次加载失败时只显示“无法加载配置”，具体错误原因被前一层状态覆盖；部分页面的加载提示不包含骨架或进度语义。

建议建立统一 `AsyncState`：

- `loading`：骨架屏或加载指示，并保留页面结构，避免跳动。
- `empty`：说明为什么为空，并提供下一步主操作。
- `error`：显示用户可理解的原因、错误编号和重试按钮。
- `refreshing`：保留旧数据，只在局部显示刷新状态。
- `submitting`：锁定当前对象，不阻塞无关对象。

### P1：核心体验优化

#### 3.4 设计语言分裂

全局已定义绿色主题变量，但页面仍混用绿色、蓝色、紫色、Material 风格色值和 Emoji 图标。圆角从 4px 到 32px，阴影层级、标题字号、卡片间距也缺少统一规则。`index.css` 对所有按钮应用位移动画，连禁用或工具栏按钮也可能产生不必要的跳动。

建议把 Ant Design Token 作为唯一语义来源，并补充少量业务令牌：

| 类别 | 建议 |
|---|---|
| 主色 | 品牌绿，仅用于主操作、选中和关键链接 |
| 状态色 | 成功、警告、错误、信息各一套，不在页面内新增色值 |
| 间距 | 4 / 8 / 12 / 16 / 24 / 32 |
| 圆角 | 控件 8；卡片 12；大面板 16 |
| 阴影 | 默认卡片、浮层两级，普通卡片悬停不整体上浮 |
| 字体 | 中文优先使用系统字体；等宽字体仅用于 ID、地址和代码 |
| 页面标题 | 24px；区块标题 18px；正文 14px；辅助信息 12px |

远程加载 Google Fonts 不适合离线或受限工业网络，建议改为系统字体栈，或将确需的字体随应用发布。

#### 3.5 信息密度缺少分层

- 工作台同时展示 8 个 KPI，重要告警与一般资产信息权重接近。
- 规则列表单行包含较多直接操作，扫描效率低，误触风险高。
- Connector 页面同时展示指标、分布、筛选、批量治理和卡片列表，首屏较长。
- Connector 卡片将标签、连接摘要、预览、引用数、队列和状态信息全部平铺。

建议：

- 工作台首屏保留“运行中、失败、事件吞吐、最近事件”4 个运维 KPI；资产类指标放到次级区块。
- 规则行只保留“部署/取消部署”和“查看”两个高频入口，其余操作放到更多菜单。
- Connector 顶部指标折叠为 4 个核心数字，分布信息移入筛选器或可展开概览。
- Connector 卡片默认只显示名称、协议、状态、目标地址、引用数和主要操作；队列、策略与诊断放到详情抽屉。

#### 3.6 导航和命名需要收敛

当前一级导航结构基本合理，但存在一个未使用的旧 `Navigation` 组件，且界面中混用中文、英文和缩写，例如 `Connector`、`Enabled`、`Disabled`、`Runtime`。

建议：

- 删除或归档未使用的旧导航实现，避免后续误用。
- 一级导航保持：工作台、规则、运行监控、插件、连接资源、系统设置。
- 面向业务用户的主标签使用中文；`Connector ID`、`Plugin ID` 等技术字段作为次级说明保留英文。
- 深层页面增加面包屑，例如“运行监控 / 规则实例 / 节点详情”。

### P2：可访问性、性能和工程质量

#### 3.7 可访问性不足

静态审查仅发现 10 处 `aria-*` 属性，而页面有 85 个原生按钮和大量自定义交互。多处状态依赖颜色，原生输入的焦点样式不统一，图编辑和运行态拓扑的键盘操作也没有形成标准。

建议最低目标为 WCAG 2.1 AA：

- 所有图标按钮提供可读名称；装饰 Emoji 不承担唯一含义。
- 状态同时使用文字、图标和颜色。
- 所有输入与可见标签建立关联，错误信息通过 `aria-describedby` 关联。
- 保留清晰的 `:focus-visible` 焦点环，不用 `outline: none` 后不补替代样式。
- Modal 打开后焦点进入，关闭后返回触发点。
- 动画遵守 `prefers-reduced-motion`。
- React Flow 提供列表式替代视图或可键盘访问的节点导航。

#### 3.8 页面文件过大

Connector、规则列表、节点详情、JSON Schema Renderer 和 Flow Canvas 均超过 700 行。请求、状态、字段定义、转换函数、布局和样式集中在单文件中，增加修改冲突和回归风险。

建议按“业务区块”拆分，而不是过度细化：

```text
pages/rules/
  RuleListPage.tsx
  RuleToolbar.tsx
  RuleTable.tsx
  RuleActions.tsx
  useRuleList.ts

pages/connectors/
  ConnectorsPage.tsx
  ConnectorOverview.tsx
  ConnectorFilters.tsx
  ConnectorCard.tsx
  ConnectorEditor.tsx
  useConnectors.ts
```

数据请求与页面显示状态放入 hooks；纯展示组件只接收值和回调；样式进入 CSS Module 或共享组件，不再继续增加页面级大对象。

#### 3.9 构建体积与技术栈存在债务

当前最大异步包 gzip 为 375.83 kB，主包为 257 kB。项目同时使用 React 19、React Scripts 5、TypeScript 4.9，并保留了面向 React Router 5 的类型包，长期维护风险较高。

建议：

- 确认 Excel 导入导出仅在用户触发时动态加载 `exceljs`。
- React Flow、CodeMirror、Recharts 和 JSON Schema 编辑器按实际页面/面板二次懒加载。
- 对规则编辑器、Connector 编辑器和运行态图表分别设置包体预算。
- 移除无效的 `@types/react-router-dom`，并评估从 Create React App 迁移到 Vite；迁移单独立项，不与视觉重构同时进行。
- 更新 Browserslist 数据并固定受支持浏览器范围。

#### 3.10 测试缺少用户旅程覆盖

现有 53 项测试全部通过，是很好的基础，但主要是组件和结构测试。当前没有明确的端到端、无障碍和截图回归基线。

建议增加：

- E2E：登录、规则创建、部署、取消部署、Connector 创建、配置保存、运行态下钻。
- 重复点击：部署、取消部署、保存、删除只能产生一次请求。
- 错误恢复：接口 401、403、409、500、超时和网络断开。
- 响应式：1440、1024、768、390 四个视口。
- 无障碍：关键页面自动扫描 + 键盘走查。
- 视觉回归：应用头部、规则列表、Connector 卡片、配置表单、运行态 DAG。

## 4. 推荐的信息架构

一级结构保持稳定，避免用户重新学习：

```text
工作台
规则管理
  规则列表
  新建 / 编辑
  生命周期
运行监控
  实例总览
  拓扑
  节点详情
  边详情
资源管理
  插件
  连接资源
系统设置
  系统配置
  用户管理
```

桌面端可以继续使用顶部导航；当宽度不足 1200px 时将一级导航收进抽屉。若未来一级模块超过 7 个，再评估改为左侧导航，不建议当前立即切换。

## 5. 统一页面与组件方案

### 5.1 页面模板

每个列表或配置页面统一为：

```text
面包屑（深层页面才显示）
页面标题 + 一句话说明 + 主操作
关键状态 / KPI（可选）
筛选与搜索
主体内容
分页 / 批量操作
```

避免页面内部再次创建不同风格的“大标题卡片”。标题区、内容区、错误区和底部操作区应来自共享模板。

### 5.2 首批共享组件

| 组件 | 用途 |
|---|---|
| `PageLayout` / `PageHeader` | 页面宽度、标题、说明、面包屑、操作 |
| `ActionButton` | 统一异步锁、加载、危险操作和权限态 |
| `StatusTag` | 规则、实例、插件和 Connector 的状态映射 |
| `AsyncState` | 加载、空数据、错误、重试、刷新 |
| `FilterBar` | 搜索、筛选、重置、窄屏折叠 |
| `DataTable` | 表格密度、分页、固定操作列和响应式 |
| `DetailDrawer` | 列表页查看诊断和次级详情 |
| `FormSection` | 配置与 Connector 表单分组、帮助和校验 |

### 5.3 状态文案

统一状态词，禁止同一状态出现多套文案：

| 领域 | 建议文案 |
|---|---|
| 规则部署 | 未部署、部署中、运行中、取消部署中、部署失败 |
| 启停 | 已启用、已停用 |
| Connector | 未检测、可用、不可用、繁忙、退避中 |
| 插件 | 已加载、已停用、启动失败、不兼容 |
| 保存 | 未修改、有未保存修改、保存中、已保存、保存失败 |

## 6. 分阶段实施计划

### 阶段 A：设计基础与公共交互

范围：

- 整理 Ant Design 主题令牌和业务状态令牌。
- 建立 `PageLayout`、`PageHeader`、`ActionButton`、`StatusTag`、`AsyncState`、`FilterBar`。
- 增加全局 `focus-visible`、禁用态、减弱动画和响应式断点。
- 停止新增内联颜色和新的原生按钮样式。
- 处理远程字体依赖和未使用的旧导航组件。

验收：同类操作在任意页面具有相同高度、颜色、加载、禁用和反馈方式。

### 阶段 B：高频页面

规则列表：

- 收敛行内操作，固定主要操作，其他操作进入更多菜单。
- 使用共享筛选栏、表格和分页。
- 保留当前按规则 ID 锁定异步操作的机制。
- 增加窄屏摘要模式、局部刷新和错误重试。

Connector：

- 减少首屏概览高度。
- 卡片仅展示决策所需信息，详细状态放入抽屉。
- 统一批量操作与单卡操作的锁定和反馈。
- 明确“连接可达性”与“当前会话”是不同状态，避免把按需连接显示为长期断开。

配置：

- 首次加载失败时展示具体原因和重试。
- 增加未保存修改提示、离开页面确认、字段级错误定位。
- 将“需要重启”改为明确的影响提示，并在可判断时标出具体配置项。

### 阶段 C：编辑器与运行态

- 规则编辑器采用可调整宽度的节点面板、画布和属性面板。
- 提供“适应画布、定位异常节点、撤销/重做、保存状态”固定工具栏。
- 运行态默认突出异常和最新活动，减少持续闪烁动画。
- 节点、边详情使用一致的面包屑和详情抽屉/页面规则。
- 无有效边实例时显示普通文本，不生成可点击链接。
- 为拓扑提供可搜索节点列表，兼顾大图和键盘用户。

### 阶段 D：质量与性能

- 拆分超大页面文件，建立页面级数据 hooks。
- 完成重型模块二次懒加载和包体预算。
- 增加 E2E、无障碍和视觉回归流水线。
- 评估并单独执行 Vite 与依赖升级。

## 7. 建议验收指标

### 一致性

- 新代码不增加硬编码状态色；颜色从主题或状态映射获取。
- 页面业务代码不新增自定义原生按钮，特殊画布控件除外。
- 所有列表页使用同一套加载、空数据、错误和分页组件。

### 交互

- 任意异步按钮连续点击只产生一次请求。
- 请求进行中能看见对象级进度，完成后数据自动同步。
- 失败后保留用户输入，并提供清楚的重试或修正入口。
- 危险操作都显示对象名称和影响范围。

### 响应式与可访问性

- 1440、1024、768、390 宽度下无关键操作不可达。
- 页面可仅用键盘完成登录、筛选、规则部署、Connector 编辑和配置保存。
- 文本与背景对比度达到 WCAG AA；焦点始终可见。
- 200% 缩放下不遮挡主要内容和操作。

### 性能与质量

- 主包 gzip 目标小于 200 kB；单个业务异步包目标小于 250 kB。若第三方库无法满足，需记录例外和加载策略。
- 关键页面首次交互不被 Excel、图表或编辑器模块阻塞。
- 核心用户旅程具备 E2E，关键页面具备无障碍和视觉回归检查。
- 生产构建、现有单元测试和新增体验测试全部通过。

## 8. 推荐首个迭代

首个迭代只做基础统一和三个高频页面，不调整后端接口：
